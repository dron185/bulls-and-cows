# Bulls and Cows — Design

## 1. Структуры данных и алгоритмы

### Состояние игры (`src/core/state.ts`)

Состояние — **неизменяемый plain-объект** (`GameState`), который никогда не
мутируется. Каждый переход (`startGame`, `addGuess`, `winGame`, `resetGame`)
возвращает новый объект через spread (`{ ...state, history: [...state.history, entry] }`).
Иммутабельная история представлена как `readonly GuessEntry[]`. Это
изолирует все DOM-эффекты от ядра и делает каждый переход тривиально
тестируемым.

### История

Используется **массив неизменяемых записей `GuessEntry`** (append-only,
амортизированно O (1) через `[...history, entry]`). Записи никогда не
редактируются — это соответствует требованию «старые записи не меняются и не удаляются».

### Рекорды (`src/core/records.ts`)

Список топ-N в `localStorage` под одним ключом. У каждой записи есть
`settings` (`length`/`base`) в качестве бейджа. Компаратор сортировки:
сначала меньшее число попыток, затем меньшее время. Обрезается до 10 записей.

### `evaluateGuess`

Чисто функциональный пайплайн из HOF массивов:

1. Нормализация в массивы в нижнем регистре (`[...secret.toLowerCase()]`).
2. **bulls** = `guess.reduce((n, ch, i) => ch === secret[i] ? n+1 : n, 0)`.
3. Строим `secretSet = new Set(secretChars)`.
4. **cows** = `guess.reduce((n, ch, i) => ch === secret[i] ? n : secretSet.has(ch) ? n+1 : n, 0)`.

Никаких ручных счётчиков в цикле — один reduce на каждый показатель.

### `countPossibleSecrets`

Рекурсивное тождество `count(l,b) = b * count(l-1, b-1)`, базовые случаи
`count(0,·)=1` и `count(l>b)=0`. Обёрнуто `memoize(fn)` (заодно демонстрация
переиспользуемого HOF). Экспортируется мемоизированная версия, а рекурсивный
вызов идёт через мемоизированную привязку — все промежуточные пары кэшируются.

## 2. Big O

| Функция                | Сложность                                               | Обоснование                                                                                                                                                           |
| ---------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generateSecret`       | **O(n²)**, где n — длина                                | `pickRecursive` вызывается n раз; каждый шаг создаёт новый пул через `slice` + spread (`O(base)`), итого O(n·base) = O(n²) при n ≤ base. Вполне достаточно при n ≤ 6. |
| `evaluateGuess`        | **O(n)**, где n — длина                                 | Два линейных `reduce` + построение одного `Set`, каждое O(n).                                                                                                         |
| `isValidGuess`         | **O(n)**                                                | `every` и вставка в `Set` — O(n); `createDigitValidator` — O(1) на символ (фиксированный размер алфавита).                                                            |
| `countPossibleSecrets` | **O(n)** при первом вызове, **O(1)** после (мемоизация) | Глубина рекурсии n; каждый закэшированный уровень — O(1). Ключ кэша = строка `length:base`.                                                                           |

## 3. Принципы чистого кода

- **Чистые функции**: каждая функция в `src/core/` без побочных эффектов.
  `generateSecret` принимает `random` параметром → детерминированные тесты.
- **Маленькие одноцелевые функции**: `createDigitValidator` возвращает только
  предикат; `memoize` только кэширует; `addRecord` только вставляет+сортирует.
- **Осмысленные имена**: `isValidGuess`, `countPossibleSecrets`, `DIGITS_BY_BASE`.
- **Без магических значений**: `BASES`, `LENGTHS`, `MAX_RECORDS`, `STORAGE_KEY` —
  именованные константы.
- **DRY**: `createDigitValidator` переиспользуется в `isValidGuess` и в живом
  фильтре ввода (`src/ui/main.ts`); `memoize` — единая дженерик-утилита вместо
  ad-hoc кэшей.
- **Иммутабельность**: переходы в `state.ts` через spread, без `push`/мутаций;
  `history` — `readonly GuessEntry[]`.
- **HOF / каррирование**: `createDigitValidator(base)` (каррированная фабрика),
  `memoize(fn)` (HOF), повсеместные `map/filter/reduce` в `evaluateGuess` и UI.
- **Без `innerHTML`**: UI построен исключительно через `document.createElement` и
  `textContent` в `src/ui/main.ts`.
- **Ошибки как обратная связь, а не throws, в UI**: ядро бросает ошибки для
  программных ошибок (неверная база / несовпадение длин), а UI превращает
  невалидный ввод в inline-сообщения.
